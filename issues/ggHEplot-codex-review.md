# 1. Summary

- **Keep the computation independent of graphics, and store full-space SSP matrices.** Derive scaled shapes and boundary points for a selected view. This lets base graphics, ggplot2, and `pairs()` share the same computation while preserving the dimension used for evidence scaling.
- **Fix repeated-measures hypotheses before using the prototype as a drop-in replacement.** The current `heplot.mlm()` combines a hypothesis in the original response coordinates with E in within-subject contrast coordinates. The prototype’s `P = P[[iterm]]` gives the appropriate hypothesis in the active contrast space. Term selection has a related coordinate-space problem.
- **Treat rank as a property of the displayed view.** Rank-one H matrices are routine for single-df terms. Render them as segments, handle rank zero explicitly, and use a consistent tolerance for rank and geometry.
- **Keep the existing `"heplot"` result and introduce a separate computation class.** Existing callers depend on the coordinate matrices, labels, and return structure. A computation object can support new views without changing that contract.
- **Make the comparison script assert invariants.** It exercises both size modes, integer and named views, and several singular H matrices, but it reports differences without asserting parity. It also cannot establish that the shared geometry is correct.
- **Start ggplot2 with a plot-data extractor and a small renderer for the computation class.** Ordinary ggplot2 layers suffice. A custom stat can receive the full computation object as a parameter, so the two mapped axes place no inherent limit on evidence scaling.

# 2. Central design

The right abstraction is an **HE computation in a declared response space**. In an ordinary MANOVA that space is the fitted responses. In a repeated-measures plot it is the selected within-subject contrast block. A coordinate view selects a principal submatrix. A linear view with basis `A` uses `crossprod(A, SSP %*% A)` and projects the center and means by the same `A`. Preserve the evidence threshold from the declared test space when displaying such a projection. A test defined on a reduced response space is a different operation. [Design notes, full-space shapes](/C:/R/Projects/heplots/issues/ggHEplot.md:62) · [Base H scaling](/C:/R/Projects/heplots/R/heplot.R:529)

I would store raw E and H, residual df, per-H hypothesis df, a stable ID and display label for each H, and the center. Record the effective ANOVA type and response-space metadata, including original response names, the active basis `P` for repeated measures, and active coordinate names in order. `iterm` alone cannot reconstruct a user-supplied contrast basis. Treat the plotted dimension, resolved axes, point resolution, limits, and drawing styles as view or renderer settings. `size`, `alpha`, and `level` can be defaults for views. The evidence reference dimension can normally be derived from the active SSP dimension and should travel with a view if the view is stored independently. [Prototype object](/C:/R/Projects/heplots/dev/heplot_compute.R:140) · [Design notes, radius](/C:/R/Projects/heplots/issues/ggHEplot.md:91)

The factor means are optional annotations. The prototype computes **observed marginal means** for each factor in the fitted model frame. In an unbalanced factorial or ANCOVA model, those means need not describe the adjusted effect shown by H. Keep the factor identity with the level, compute the means only when requested if practical, and document the estimand. A separate plot-data step can emit paths, segments, points, labels, and limits for either renderer. That step is also useful to callers who want coordinates without drawing. [Prototype means](/C:/R/Projects/heplots/dev/heplot_compute.R:130) · [Base means and limits](/C:/R/Projects/heplots/R/heplot.R:565)

# 3. Open decisions

### 1. Full-space rank and view rank

Full-space rank is useful for diagnostics. View rank governs geometry. A rank-two H can project to a segment, and a nonzero rank-one H can project to a point. Hypothesis df still controls the critical value. [Design notes, decision 1](/C:/R/Projects/heplots/issues/ggHEplot.md:232) · [Prototype rank calculations](/C:/R/Projects/heplots/dev/heplot_compute.R:99)

**Recommendation.** Compute view rank during geometry generation and derive full-space rank on demand for summaries. Keep `df` distinct from either rank.

### 2. Pre-scaled shapes or raw SSP

The stored prototype shape is reversible when `dfe` and the applied factor are valid. Thus changing `size` or `alpha` is already mathematically possible without running `Anova()` again. Raw SSP makes that operation explicit and avoids treating both a derived matrix and its scaling metadata as authoritative. The existing `lambda.crit()` defaults to **Roy’s largest-root critical value**, despite its name. E uses `SSPE / dfe`, and H uses `SSPH / (dfe * critical)` in evidence mode. [Design notes, decision 2](/C:/R/Projects/heplots/issues/ggHEplot.md:236) · [Critical-value implementation](/C:/R/Projects/heplots/R/heplots-internal.R:26)

**Recommendation.** Store raw SSP and df. Derive shapes with a shared helper and expose a scaled-shape accessor for uses such as `ellipse.axes()`. Derive `1 / dfe` and the critical value when requested.

### 3. Hypotheses in repeated-measures designs

The analysis in the notes is right. `heplot.mlm()` transforms Y and uses the E block for `iterm`, then takes H for a custom hypothesis from an untransformed `linearHypothesis()` call. Positionally selecting two rows and columns of that H does not turn original responses into contrast scores. `car`’s `P` argument transforms coefficients to `B %*% P` and E to `t(P) %*% E %*% P` before forming H. For a zero-RHS hypothesis on the between-subject coefficients, this tests \(LBP=0\). Its H is \(P^\mathsf{T}H P\), where H is the original-space SSP for \(LB=0\). [Base response transform](/C:/R/Projects/heplots/R/heplot.R:448) · [Base hypothesis calculation](/C:/R/Projects/heplots/R/heplot.R:546) · [Prototype hypothesis calculation](/C:/R/Projects/heplots/dev/heplot_compute.R:121) · [`car::linearHypothesis.mlm()` source](https://raw.githubusercontent.com/cran/car/master/R/linearHypothesis.R#L383-L408)

For Adopted, `Reg` in the `Age` view asks whether `AMED` and `BMIQ` jointly predict components of the **age profile** represented by those contrasts. With the within-subject intercept basis, it instead asks about a constant-across-ages component, with the exact scaling set by the basis. The prototype test’s comment and the notes report a discrepancy for `Reg`. The source establishes the coordinate mismatch independently of the reported numerical difference. [Adopted comparison](/C:/R/Projects/heplots/dev/heplot_compute-test.R:60)

**Recommendation.** Define custom hypotheses in the active response space, document the interaction interpretation, and ship this as an explicit correctness fix. Assert `P' H P` against an independent reference. If a future API accepts nonzero RHS matrices, specify which basis they inhabit.

### 4. Unnamed hypotheses

The prototype’s fallback is useful for character hypotheses. Its blanket `paste()` also flattens numeric contrast matrices into labels, and explicit `NA` names survive. Display labels can collide with each other, with terms, or with `"Error"`. Grouping plot rows by display label can then join distinct boundaries. [Prototype naming and row construction](/C:/R/Projects/heplots/dev/heplot_compute.R:116) · [Base return naming](/C:/R/Projects/heplots/R/heplot.R:615)

**Recommendation.** Give each entry a stable ID and use it for grouping. Use short expression labels for unnamed character hypotheses and numbered labels for unnamed matrix hypotheses. Preserve legacy `H` names during the refactor.

### 5. Radius and dimension

The existing 2D and 3D paths use different F-based radii. In evidence mode the H and E radii share the same multiplier. Changing `level` changes their displayed extent while leaving their relative scaling unchanged. `alpha` sets the evidence threshold. [2D radius](/C:/R/Projects/heplots/R/heplot.R:503) · [3D radius](/C:/R/Projects/heplots/R/heplot3d.R:457)

**Recommendation.** Resolve radius in the view from its dimension, `level`, and residual df. Document `level` and `alpha` separately.

### 6. Terms with incompatible SSPs

Dimension matching cannot establish that two matrices refer to the same response space. Two within-subject blocks can have the same number of contrasts, and the base method can also admit a larger matrix when the requested indices happen to fit. [Prototype filter](/C:/R/Projects/heplots/dev/heplot_compute.R:107) · [Base filter](/C:/R/Projects/heplots/R/heplot.R:527)

**Recommendation.** Select defaults by response block. Reject an explicitly requested term from a different block with an error naming the valid terms. Validate the matrix dimensions and coordinate order after selecting the block.

### 7. Center

`data` is assigned from `model.frame(mod)` before the `missing(data)` check. The effective center is the ordinary column mean of the fitted cases in the active response space. Both paths use unweighted centering, even for a weighted fit. [Base model frame](/C:/R/Projects/heplots/R/heplot.R:434) · [Base center](/C:/R/Projects/heplots/R/heplot.R:498) · [Prototype center](/C:/R/Projects/heplots/dev/heplot_compute.R:130)

**Recommendation.** Use `colMeans()` directly and preserve the existing centering convention. Document it alongside the means.

### 8. New class or extended `"heplot"` result

The two objects have different contracts. The computation supports multiple views. The existing invisible result describes one drawing and omits limits in `add = TRUE` mode. Adding fields to its list can also change code that enumerates or compares the result. [Design notes, decision 8](/C:/R/Projects/heplots/issues/ggHEplot.md:260) · [Base return branches](/C:/R/Projects/heplots/R/heplot.R:642)

**Recommendation.** Use a new computation class and keep the legacy return shape. Defer attaching the computation until there is a concrete annotation API that needs it. If that API needs the exact drawing, preserve the resolved view settings with the computation.

# 5. ggplot2 route

I agree with **refactor → plot-data extractor → small ggplot2 prototype**. Make the extractor the primary contract. A `tidy()` method can delegate to it once the row schema is settled. Prototype `autoplot()` on the new computation class or provide an explicit `ggheplot(mod, ...)` wrapper. `autoplot.mlm()` would register an interpretation of a general model class and can change dispatch for users whose plotting packages provide an inherited `lm` method. `fortify()` adds little for this workflow, and ggplot2 has deprecated several model-specific fortifiers. [Proposed rollout](/C:/R/Projects/heplots/issues/ggHEplot.md:211) · [ggplot2 extension generics](https://ggplot2.tidyverse.org/reference/) · [ggplot2 changelog](https://ggplot2.tidyverse.org/news/index.html) · [ggfortify](https://github.com/sinhrks/ggfortify)

The argument against `stat_he()` applies to **a stat that attempts to reconstruct the model from `x` and `y` alone**. A stat can accept the model or the full HE computation as a layer parameter and use `compute_panel()` when panel-level work is needed. A wrapper can expand the object before building layers. Passing only `p` can recover the threshold for a simple between-subject coordinate view if the model rows, design matrix, weights, and df agree. It cannot recover a repeated-measures basis or rows excluded because another response was missing. `geom_smooth()` already establishes `formula` as a normal stat parameter. [Design notes, stat proposal](/C:/R/Projects/heplots/issues/ggHEplot.md:171) · [ggplot2 `Stat` API](https://ggplot2.tidyverse.org/reference/Stat.html) · [ggplot2 `geom_smooth()`](https://ggplot2.tidyverse.org/reference/geom_smooth.html)

For the first renderer, use `geom_polygon()` or `geom_path()` for rank two, `geom_segment()` for rank one, and an explicit policy for rank zero. Build E first and group by stable ellipse ID. An `autolayer()` method or a helper returning ordinary layers gives users composition without a custom stat or geom. `ggforce::geom_ellipse()` is an existing option for drawing center/axes/angle parameterizations, although direct point expansion gives heplots control over rank, compatibility, and dependencies. Faceting a common computation across coordinate pairs is straightforward once each view has a panel key. Subgroup facets that each perform inference need one model or computation per subgroup and a stated sample and scaling policy. [ggplot2 `autolayer()` source](https://github.com/tidyverse/ggplot2/blob/main/R/autoplot.R) · [ggforce `geom_ellipse()`](https://ggforce.data-imaginist.com/reference/geom_ellipse.html)

Keep the first renderer in heplots with ggplot2 optional. ggplot2 is already in `Suggests`. A separate package becomes worthwhile if the extension develops its own maintenance needs and can depend on a stable heplots computation API. [DESCRIPTION](/C:/R/Projects/heplots/DESCRIPTION:45)

Keep established arguments such as `terms`, `hypotheses`, `iterm`, `size`, `level`, and `alpha`. Canonicalize aliases internally while accepting existing spellings. Keep means and annotation data accessible. `as.data.frame()` is reasonable convenience for an ellipse-coordinate table if its default pair and geometry are documented. If `tidy()` is added, document whether rows are vertices or per-effect summaries. The package already uses `generics` for `glance()`.
